# BE-03 Operator Account Management Plan

**Goal:** Give a local operator safe account creation, password reset, and deactivation commands, with future authentication able to reuse the password and normalization helpers.

**Spec:** `docs/TICKETS.md` BE-03 and `docs/BACKEND.md` authentication section.

**Boundaries:** Keep all account writes in `auth/accounts.py`, password primitives in `auth/passwords.py`, and CLI parsing/prompts in `auth/cli.py`. No public account HTTP endpoint. Use the existing PostgreSQL user/session tables and transaction manager; no schema migration is needed.

**Key decisions:** Canonical email is validated, trimmed, then casefolded for uniqueness. Argon2id hashes use the library's documented defaults. Passwords enter through `getpass`, never arguments or logs. Reset and deactivation revoke active sessions in the same database transaction as the account change. Database unique constraints remain the final duplicate guard.

**Tests first:** (1) Passwords store only Argon2 hashes and verify correctly. (2) Case variants collide, malformed emails fail. (3) Reset changes the hash and revokes sessions; deactivate revokes sessions and makes the account inactive. (4) CLI prompts without echo or password arguments, exits clearly on duplicates/missing users, and does not print secrets.

**Verification:** Full PostgreSQL suite, Ruff, `uv build`, CLI smoke with a disposable database, and focused review. The review caught `getpass`'s echoed-input fallback; a regression test now ensures the command fails before reading when secure prompting is unavailable. Mark BE-03 Done after BE-04 verifies deactivated users cannot log in.
