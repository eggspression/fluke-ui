# MVP-03 Owned Experiments and Queued Runs Plan

**Goal:** Let authenticated users save and edit a small FLUKE configuration, then queue immutable run snapshots without training in an HTTP request.

**Source:** `docs/TICKETS.md` MVP-03, `docs/BACKEND.md` configuration and HTTP contract, and the implemented `RunConfig` from MVP-02.

**Boundaries at implementation time:** Reuse the runner's small validation contract and add only a name. Store experiment and run configurations as JSONB in PostgreSQL. Scope every lookup by owner. Lock the experiment row for edit and launch; an edit after any run returns `409`. The worker, logs, accuracy, and frontend belong to later tickets. Documentation was initially tracked only on `local/docs`; the user later authorized publication, as recorded below.

## Tasks and verification

1. Write PostgreSQL API tests for create/list/get/edit, defaults, invalid forms, cross-user denial, run launch and history, snapshot stability, and edit blocking. Observe missing-route failures.
2. Add experiment/run models and additive Alembic migration; update readiness revision and metadata imports. Verify fresh migration, downgrade/reapply, and `alembic check`.
3. Add a small service for owned transactions and a thin FastAPI router. Create only `QUEUED` runs. Verify focused and full backend suites, Ruff, and package build.
4. Review the code and correct findings. Update the implementation guide, roadmap, backend design, handoff, and setup guide with verified behavior and manual tests.

## Result

- The new API tests first failed with `404`, then passed after route, model, service, and migration work.
- A focused review found that the inherited `mu` field accepted JSON booleans and numeric strings. A regression test failed on `mu: true`; strict numeric validation made it pass.
- The local application database upgraded to `20261008_0003`; Alembic reported no metadata drift.
- The full PostgreSQL and runner-enabled backend suite passed 74 tests without skips. Ruff lint/format and `uv build` passed.
- Code was committed on `mvp-03-api`; documentation was committed separately on `local/docs`. The user later authorized publishing both histories to `origin/main` on 2026-10-10.
