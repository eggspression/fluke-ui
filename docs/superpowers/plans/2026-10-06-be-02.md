# BE-02 Database Foundation Implementation Plan

> **For agentic workers:** Use test-driven-development and verification-before-completion. Execute this plan in the current session on branch `be-02-database`.

**Goal:** Add transactional PostgreSQL persistence, reversible initial migrations, isolated integration tests, and database readiness to the BE-01 API.

**Architecture:** SQLAlchemy creates an engine without connecting during app construction. Database sessions commit on success and roll back on failure. Alembic owns the user and login-session schema. Test fixtures create unique disposable databases from an explicit local PostgreSQL admin URL; the API checks both connectivity and Alembic revision for readiness.

**Tech stack:** Python 3.11, uv, FastAPI, SQLAlchemy 2, Alembic, psycopg 3, PostgreSQL 17, pytest, Ruff.

**Spec:** `docs/TICKETS.md` BE-02 and `docs/BACKEND.md` persistence/authentication sections.

## Global constraints

- Keep API imports free of connections, table creation, FLUKE and PyTorch.
- Use UUID primary keys and timezone-aware UTC timestamps.
- Migrations must upgrade empty PostgreSQL, downgrade, and upgrade again.
- Tests must never migrate or clear the configured application database. Their database names are generated, used once, and removed.
- Liveness stays independent of database state; readiness returns 503 for connection or revision problems without disclosing credentials.

## Review focus

- A PostgreSQL server can be reachable with an empty or stale schema.
- Transaction failure must not retain writes.
- Test setup must refuse a remote or deployment admin URL.
- Connection failure must not break app import or liveness.
- Migrations and ORM metadata must agree on table names, columns, constraints, and defaults.

## Tasks

1. Write failing readiness tests for unavailable database and missing schema. Add dependencies and minimal readiness implementation.
2. Write migration and model tests against a disposable PostgreSQL database. Implement ORM models and reversible Alembic migration. Verify upgrade, downgrade, reapply, UUID and UTC conventions.
3. Write transaction rollback and test-guard tests. Implement lazy engine/session lifecycle and safe PostgreSQL fixtures.
4. Update OpenAPI, backend setup, ticket status, and project docs. Run full pytest, Ruff, migration command, and independent review; commit focused changes on the ticket branch.
