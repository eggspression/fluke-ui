# MVP-02 FLUKE CPU Proof Plan

**Goal:** Run two-round FedAvg and FedProx proofs on sampled MNIST in fresh processes and emit validated global accuracy per round.

**Source:** `docs/TICKETS.md` MVP-02, `docs/BACKEND.md` runner rules, and the local FLUKE checkout at `37c54630f0b4d9d6164f003cbed0811019acc5e1`.

**Boundaries:** Keep the API install and imports free of FLUKE and PyTorch. The runner accepts a small JSON snapshot of the future form fields plus server-owned output and dataset directories. It maps only supported choices into FLUKE configuration, constructs the algorithm through public APIs, and records metrics through an observer. A successful exit requires every requested round and finite accuracy values. An exception, interrupted/early run, or result write failure exits nonzero and leaves a diagnostic log. Do not add HTTP, database, worker, or catalog code here.

## Tasks

1. Add failing tests for runner input validation, fixed FLUKE choices, and rejection of unknown fields or invalid FedProx/FedAvg values. Implement the smallest snapshot validator and configuration builder.
2. Add failing tests for observer-derived result validation: complete ordered rounds, finite accuracy, no result on short/failed training, and a parseable result file. Implement the result collector and atomic write after training.
3. Pin FLUKE as an optional runner dependency. Implement the CLI entry point and public API construction. Run deliberate invalid-input and execution-failure subprocess checks; keep imports lazy.
4. Run real FedAvg and FedProx two-round CPU subprocesses on sampled MNIST. Adjust only the sample fraction needed for a usable proof; record exact runtime and results. Run the complete backend suite, Ruff, and build.
5. Update `backend/README.md`, `docs/TICKETS.md`, and `docs/IMPLEMENTATION_GUIDE.md` with verified behavior. Commit code on `mvp-02-runner`; keep documentation tracked only on local `local/docs` and unpushed.

## Review focus

- A zero process exit without all requested rounds or per-round accuracy must fail.
- The final FLUKE evaluation may repeat the last round; it must not create a duplicate result.
- Unsupported user fields must not become import names, paths, or FLUKE configuration.
- A stale result from an earlier attempt must not survive a failed rerun.
- A dataset download or runtime blocker must be reported without marking the ticket complete.
