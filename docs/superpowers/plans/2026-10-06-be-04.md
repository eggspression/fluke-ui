# BE-04 Authentication Plan

**Goal:** Let operator-created accounts log in, inspect their own identity, and log out through database-backed eight-hour JWT sessions.

**Contract:** `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/me`; signed HS256 bearer tokens with user and session identifiers; generic 401 for invalid credentials and tokens. Responses disclose no password hash or session internals. An authenticated-user dependency must be reusable by later owned-resource routes.

**Safety:** Require a 32-character or longer signing secret from configuration. Lock the user row while verifying credentials and inserting a session so password reset and deactivation cannot race a login. Check active user, session ownership, expiry and revocation in the database on every authenticated request. Permit only explicitly configured development CORS origins. Keep credentials and authorization headers out of logs.

**Tests first:** API login/me/logout; bad credentials, invalid/expired/forged tokens, revoked and inactive sessions; password reset and deactivation; error envelope and validation fields; origin allowlist and response/log redaction; missing secret. Run the full PostgreSQL suite, Ruff, build, OpenAPI snapshot, and review before merging.

**Result:** All 45 tests pass with PostgreSQL, including an operator-command to API login walkthrough. Ruff, package build, Alembic schema check, and independent review pass. The review found no blocking auth issue; rejected CORS preflights and unexpected 500s now use the shared error envelope and request-ID header.
